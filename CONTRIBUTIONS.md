# Contributions

Every team member must document substantive contributions.

| Member | Role | Issues / Work Packages | Key Files / Models | Pull Requests | Evidence |
|---|---|---|---|---|---|
| | | | | | |

## Working agreement
Teams should:
- create issues before significant work;
- use scoped branches;
- make meaningful commits;
- open pull requests for integrated work;
- review each other's changes;
- avoid uploading the complete project as one final commit.

## Branch examples
- `feature/ingestion-collisions`
- `feature/staging-models`
- `feature/data-quality-tests`
- `docs/technical-handover`

## Commit examples
- `feat: add collision ingestion pipeline`
- `test: validate casualty collision references`
- `docs: document source schema changes`
- `fix: make annual load idempotent`

The Git history should make the team's collaboration understandable to an external reviewer.
